BantAI v1.1.0 Hybrid AI Decision-Support Architecture

LOCAL DOCKER DEPLOYMENT
-----------------------
Browser extension -> 127.0.0.1:8000 -> detector container
                                           |
                                           +-- frozen RF V4-B
                                           +-- frozen XLM-R V1
                                           +-- indicator engine + deterministic fusion
                                           +-- Companion pairing/outbox state volume
                                           |
                                           +-- private Docker network
                                                   |
                                                   +-- platform container :8080
                                                           |
                                                           +-- MySQL container :3306
                                                           +-- backend-only Cloud AI gateway

Docker exposes detector port 8000 and platform port 8080 on host loopback only.
The database is not published to the host. All three services use
`restart: unless-stopped` and start in dependency/health-check order.

ACTIVE TAB
    |
    +-- exact tab.url ----------------> Frozen RF URL V4-B
    |                                      |
    |                                      +-- independent SAFE / SUSPICIOUS
    |                                      +-- optional minimized URL AI context
    |                                              |
    |                                              +-- always enabled; RF warnings only
    |                                              +-- origin only; no path/page content
    |                                              +-- HIGH-confidence clean -> NO STRONG WARNING SIGNS
    |                                              +-- lower-confidence disagreement -> NEEDS CAUTION
    |
    +-- Gmail / Outlook / Yahoo only
            |
            +-- provider extractor: sender + subject + visible current body
                    |
                    +-- Frozen XLM-R Email V1
                    |
                    +-- Explainable Philippine Scam Indicator Engine
                    |
                    +-- Cloud AI Review always enabled
                    |       |
                    |       +-- redact + minimize + strict LLM schema
                    |                    |
                    |                    +-- valid result or UNAVAILABLE
                    |
                    +-- Deterministic Email Fusion (Rules A-H)
                            |
                            +-- NO STRONG WARNING SIGNS
                            +-- NEEDS CAUTION
                            +-- SUSPICIOUS SIGNS FOUND

The URL signal is shown independently and never enters email fusion. A SAFE
webmail URL cannot downgrade an email warning.

DETERMINISTIC RULES A-H
-----------------------
A. Clean XLM-R + clean LLM + no strong/critical marker -> NO STRONG WARNING SIGNS.
B. Local/LLM disagreement -> NEEDS CAUTION.
C. LLM suspicious without local corroboration -> NEEDS CAUTION.
D. XLM-R suspicious while LLM is clear -> NEEDS CAUTION unless a local marker
   supplies the second suspicious source.
E. A lone strong/critical marker -> NEEDS CAUTION.
F. Any two independent suspicious sources -> SUSPICIOUS SIGNS FOUND.
G. Other ambiguous/incomplete combinations -> NEEDS CAUTION.
H. With cloud OFF/UNAVAILABLE: local clean -> NO STRONG WARNING SIGNS; one local
   warning source -> NEEDS CAUTION; XLM-R plus strong/critical marker ->
   SUSPICIOUS SIGNS FOUND.

No rule produces an overall numeric risk score.

COMPLETE-RESULT POPUP FLOW
--------------------------
1. A new supported email or eligible address change starts a sequence-bound request.
2. Local results are stored without opening the automatic popup.
3. The applicable redacted/origin-only cloud request runs automatically.
4. The popup opens for approximately five seconds only after both outputs have
   complete assessment states.
5. Cloud CHECKING or UNAVAILABLE states never trigger an automatic popup.
6. A result fingerprint opens automatically at most once; focus, tab clicks,
   repeated extraction, and page-complete events do not reopen it.
7. Manually opening the toolbar popup never schedules a five-second close.

Cloud URL requests for the same normalized hostname are coalesced while in
flight. Provider quota/time-limit responses start a short backend cooldown;
subsequent URL scans return the cached operational state immediately while the
frozen local detector continues to apply.

Gemini model failover is backend-only. A quota response from the configured
primary model causes the same minimized review to be attempted once with the
configured fallback model. A successful fallback becomes the active model for
the remainder of that backend process. Other provider errors never switch models.

PRIVACY BOUNDARY
----------------
- The extension stores only transient results and the cloud preference Boolean.
- Raw email bodies are sent only to the local backend and are never logged/stored.
- The cloud payload retains semantic context after best-effort sensitive-value
  redaction and beginning/ending truncation.
- Only normalized hashes and validated results are cached in backend memory.
- URL cloud review caches only a normalized hostname fingerprint and validated result.

STRICTLY OUT OF SCOPE
---------------------
- embedded email link extraction or scoring
- webpage crawling or HTML submission
- automatic link opening or navigation
- redirect following or analysis
- TLS analysis
- sender authentication
- overall numeric risk score
- model retraining or threshold changes
